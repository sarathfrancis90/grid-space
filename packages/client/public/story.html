Section 01

What is Agentic AI Engineering?

There is a fundamental difference between asking AI to write code and building a system where AI can build software.

💬

Vibe Coding

  • Developer prompts AI line-by-line
  • Manual copy-paste into files
  • No upfront architecture or structure
  • Breaks at scale — "works on my machine"
  • Context lost between prompts
  • Testing is an afterthought
⚙️

Agentic AI Engineering

  • Structured methodology with guardrails
  • AI agents operate autonomously on the codebase
  • Planning → Architecture → Autonomous execution
  • Automated testing and CI/CD built in
  • Full context via CLAUDE.md and agent docs
  • Human is the architect, AI is the builder

"Vibe coding is asking AI to write code. Agentic AI Engineering is building a system where AI can build software."

Section 02

The Planning Phase — BMAD Methodology

One day of human planning enabled near-autonomous AI development. Every architectural question was pre-answered before the first line of code.

CLAUDE.md Single Source of Truth (231 lines)

Mission, tech stack, ASCII architecture diagram, directory structure, 16-sprint breakdown, session protocol, commit conventions, and 12 explicit "NEVER DO" rules. The AI's instruction manual.

feature_list.json 427 Features Decomposed

Machine-readable JSON with sprint, category, priority, and pass/fail status for every feature. Both a roadmap and a live progress tracker that agents update as they complete work.

agent_docs/ 12 Deep Technical Guides

Grid rendering, formula engine, state management, formatting, auth, real-time collaboration, database schema, API design, and more. Written before any code existed.

Directory Structure — Every File Pre-Planned

17 component directories, 12 Zustand stores, route-controller-service-Prisma patterns, all decided upfront. No ambiguity during development.

Architecture Decisions — Locked In

Canvas grid (not DOM), Zustand + Immer (not Redux), Express + Prisma (not tRPC), Socket.io + Yjs CRDT (not Firebase), PostgreSQL + Redis (not MongoDB).

"Measure twice, cut once — but at machine speed."
